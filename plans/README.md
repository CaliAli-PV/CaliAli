# Plans

Implementation plans and design decisions, for whoever works on the code.

Not user documentation: everything under `docs/` is built and published as the
documentation site, including pages that are absent from the mkdocs nav, so
anything not meant for users belongs here instead.

A plan states what was decided and why, and carries a status line saying whether
it has been built. A plan that has been implemented is worth keeping: the
reasoning behind a decision is the part that is hardest to recover later from
the code alone.
